# landing-page-recipe

## Purpose
Orchestrate a landing page from business objective to production-ready design without falling into generic SaaS section patterns or treating the visual mockup as the final product.

## When to use
- New homepage/landing page, launch page, product campaign page, major redesign.

## Inputs required
- Business objective and primary conversion.
- Audience/problem/value proposition and verified proof.
- Brand/creative direction.
- Product/media inventory.
- Responsive, accessibility, performance, and implementation constraints.

## Operating principles
- Start from the user's questions and proof needs, not a section template.
- Explore several page concepts before converging.
- Product truth and evidence outrank decorative spectacle.
- Copy, layout, image, motion, and implementation must be developed in context with each other.
- Motion/3D is allowed only when it communicates product/brand behavior or materially improves understanding.
- Independent review precedes production lock.

## Workflow
1. `brand-strategist` — clarify audience/value/category tension if not already approved.
2. Research + inspiration — category, best-in-class, adjacent industries, anti-references.
3. `art-direction` — design read, creative dials, dominant idea, anti-principles.
4. `copywriter` + `headline-writing` — message hierarchy and headline territories.
5. `landing-page-layout` — explore 2–4 narrative/composition models.
6. `hero-section-design` — refine the opening decision surface.
7. `image-director` and/or `motion-designer` — specify only the media the page genuinely needs.
8. Build realistic product/proof surfaces; never fabricate metrics/testimonials/partners.
9. `brand-fit-review`, `copy-review`, and `creative-critic` — independent gate; use `creative-skeptic` for high-risk directions.
10. Implement responsive/accessibility/performance behavior and review the built result, not only static visuals.

## Deliverables
- Research/inspiration packet.
- Message hierarchy.
- Creative direction/dials.
- Page narrative and layout system.
- Hero specification.
- Image/motion/3D asset specifications where needed.
- Responsive design states.
- Review verdicts and revision list.
- Implementation/handoff package.

## Review criteria
- Page is specific to the product, not a reusable category template.
- Claims and proof are credible.
- Layout tells a coherent story with a stable CTA hierarchy.
- Visual character is strong without reducing usability.
- Motion/media improve the narrative and remain performant/accessibly replaceable.
- Built page preserves the approved design intent.

## Failure modes
- Hero + stats + feature cards + dashboard + testimonials by default.
- Designing with fake logos, metrics, or quotes.
- Huge cinematic intro before users can understand or act.
- Treating mobile as a shrunken desktop mockup.
- Generating the whole page as one image and calling it implemented.

## Handoffs
- Production Planning creates concrete asset/tool/implementation tasks.
- Asset Registry tracks approved visuals and page dependencies.
- Engineering, QA, performance, and accessibility reviews gate release.
