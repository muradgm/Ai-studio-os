# Visual System contract

Visual System is downstream of an explicitly human-selected Creative World and upstream of production UI implementation.

It turns the selected world into an operable, stress-tested visual language across real product complexity.

## Required inputs

- human-selected Creative World / Hybrid selection artifact
- frozen Product UX Architecture reference
- frozen canonical interface fixture reference
- selected-world constitution / guardrails

## Required dimensions

- brand integration
- typography
- color and semantic color
- surfaces/material
- spacing and density
- iconography
- component grammar
- interaction states
- motion system
- responsive grammar

## Proof requirements

The system must prove itself on the complete canonical screen set and on dense/edge states including long responses, code, evidence, 10+ sources, tool execution, streaming, errors, and long project memory.

Exact browser proof must preserve the canonical semantic fixture. A cleaner screenshot may not remove hard information.

## Truth boundary

Creative World selection does not equal visual approval.

A Visual System candidate may become `ready-for-visual-system-browser-proof` while all of the following remain false:

- typographyHumanApproved
- colorHumanApproved
- motionHumanApproved
- humanVisualApproval
- finalVisualSystemApproved

Final visual approval requires inspection of the exact-browser canonical + stress proof.

## AI Council Hybrid rule

For the selected Hybrid world:

- Decision Spine owns semantic structure and lineage.
- Counterpoint owns reading and human judgment.
- Threshold owns consequence/authority states only.

Do not let those responsibilities collapse into a decorative mixture.
