# icon-system-exploration

## Purpose

Create and compare an original icon-language hypothesis before full icon-family construction.

This skill owns semantic inventory, icon-world exploration, calibration proof, and the human icon-world selection boundary. It does **not** replace `icon-system-construction`, `vector-geometry-engineer`, `vector-geometry-review`, or SVG integrity.

## When to use

- after the product/brand/Visual System direction is human-approved;
- before a product icon library is scaled into production;
- when a prior icon direction such as Quiver Line exists only as a hypothesis and needs to be challenged;
- when brand-specific concepts such as Council, Evidence, Provenance, Memory, Supersede, Authority, or Verification deserve original semantic construction;
- when icons must survive 14–18px UI use rather than merely look good on a specimen board.

Do not use this skill to style-transfer Lucide, Phosphor, Heroicons, Material Symbols, or another library's geometry.

## Inputs required

- selected Creative World / Hybrid constitution;
- human-approved Visual System direction;
- Motion System constitution when future state transitions matter;
- canonical Product UX Architecture and interface fixture;
- icon semantic inventory and usage contexts;
- accessibility and implementation constraints;
- existing vector-geometry subsystem and SVG integrity contracts.

## Operating principles

- Originality is concentrated where the semantics are specific to the product.
- Familiar controls preserve convention first and inherit family geometry second.
- Semantic recognition outranks clever construction.
- Icon geometry remains monochrome; Visual System supplies semantic color.
- Quiver Line is a hypothesis until explicit human icon-world selection.
- Compare exactly the same calibration concepts, sizes, and contexts across worlds.
- Calibrate difficult icons before scaling the library.
- 14–18px is a hard rejection zone: muddiness, collapsed gaps, ambiguous pairs, or excess nodes block advancement.
- Nodes, lineage, cuts, and directional devices are allowed only when semantically justified.
- Static glyphs must work before animated icon states are designed.
- Product/app icon family comes after UI icon-language selection.
- No automatic icon-world selection.

## Workflow

1. Read the selected product/brand/Visual/Motion constitutions.
2. Author `ai-studio-os/icon-semantic-inventory@1` with 20–32 canonical concepts.
3. Classify each concept as `brand-semantic` or `convention-dominant`.
4. Select 8–10 difficult calibration glyphs that span abstract, conventional, directional, status, lineage, and boundary problems.
5. Author three controlled Icon Worlds with explicit geometry hypotheses and risks.
6. Validate each world geometry hypothesis through the existing Vector Geometry spec contract.
7. Construct calibration SVG candidates only; do not produce the full 80–120 icon library.
8. Render exact-browser specimen proof, same-concept comparisons, real UI context proof, and 12–32px optical proof.
9. Test confusing semantic pairs explicitly.
10. Run SVG integrity checks and reject construction defects.
11. Independently review semantic clarity, brand ownership, density, small-size behavior, and interface fit.
12. Keep icon-world selection null until explicit human review.
13. After human world selection, hand the selected Icon DNA into `icon-system-construction` for the ~25-icon V1 set and production vector review.

## Deliverables

- `ai-studio-os/icon-semantic-inventory@1`;
- `ai-studio-os/icon-world-exploration@1`;
- three Icon World geometry hypotheses;
- 8–10 calibration glyphs per world;
- exact-browser specimen and interface proof;
- 12/14/16/18/20/24/32px optical proof;
- confusing-pair comparison proof;
- SVG integrity report;
- `ai-studio-os/icon-world-calibration-proof@1`;
- explicit human-selection truth boundary;
- handoff to deterministic vector construction after selection.

## Review criteria

- Do brand-semantic glyphs feel native to the product rather than to generic AI software?
- Do conventional glyphs remain immediately recognizable?
- Are Evidence and Verification clearly different?
- Are Decision and Approval clearly different?
- Are History and Provenance clearly different?
- Are Memory and Activity clearly different?
- Are Authority and Blocked clearly different?
- Are Supersede and Retry clearly different?
- Does every world survive 14–18px without collapsing into noise?
- Do icons recede appropriately in dense evidence/memory states?
- Can the family remain coherent in monochrome before semantic color is applied?
- Does the geometry preserve useful future motion anchors without requiring animation for recognition?
- Do candidates pass the existing Vector Geometry and SVG integrity contracts?

## Failure modes

- drawing 100 icons before difficult calibration cases work;
- treating Quiver Line as selected because Visual System V1 once named it;
- brand-customizing Search until it becomes less recognizable;
- using nodes/lines on every glyph to manufacture family resemblance;
- producing mini flowcharts as icons;
- confusing Evidence with Verification or Supersede with Retry;
- relying on color to communicate icon meaning;
- proving only 24px/48px specimen views;
- hiding difficult UI contexts to protect a beautiful icon sheet;
- copying an existing icon library and changing stroke width;
- approving generated SVG because it renders cleanly without reviewing geometry.

## Handoffs

- `product-designer` validates semantic meaning and interface contexts;
- `art-direction` challenges family character and anti-clichés;
- `vector-geometry-engineer` owns exact production geometry after world selection;
- `icon-system-construction` scales the approved family grammar;
- `vector-geometry-review` independently audits geometry and set consistency;
- Motion System may later consume stable layer IDs, anchors, pivots, and state relationships;
- app-icon work starts only after the UI icon language is selected and proven.
